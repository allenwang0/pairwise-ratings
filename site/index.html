Choosing the next pair · Glicko-2 ratings

With Glicko-2, info-gain pairing lifts the average curve to τ 0.8 after 740 comparisons, not 1,010

The random curve creeps from 0.79 to 0.8 between 830 and 1,010 comparisons, so a small vertical gap becomes a wide horizontal one. That is where the 27 % comes from.

An average curve, not a typical run. The 27 % is read where two averaged curves cross 0.8. Runs that stall pull the random average down, so a single run usually saves much less (next section).

Per-run spread · first reach of τ 0.8

The typical run gains far less: median first reach is 670 comparisons with info gain vs 700 with random pairs

The rules differ more in how many runs stall: 25 of 100 uncertainty runs and 20 closest runs never reach 0.8, against 9 for random pairs and 6 for info gain. The intuitive shortcuts are riskier, not uniformly slower.

Rating systems · random pairs

With random pairs, Bradley-Terry ranks best: mean τ 0.841 after 1,280 comparisons, Elo 0.792

Bradley-Terry refits every skill from all results so far. Its mean curve reaches τ 0.8 at 780 comparisons, against 1,010 for Glicko-2 with the same random pairs.

Methodology

How this was measured

Each run draws 32 players with hidden skills from N(0, 1) on the logit scale. Player i beats j with probability 1 / (1 + esj − si), the same model the rating systems assume. Every condition plays 1,280 comparisons per run, over seeds 0–99; a seed gives every condition the same players, so the conditions are compared on identical pools.

Every 10 comparisons the estimated skills are ranked and scored against the true order with Kendall τ. Curves are the mean over runs, with a 95 % normal-approximation interval of the mean (1.96 standard errors). “First reach” is, per run, the first checkpoint with τ ≥ 0.8. results.json also records Spearman ρ for every curve.

What this shows

  • With Glicko-2, info-gain pairing reaches a ranking accuracy target sooner on the average curve, and leaves fewer runs short of it.
  • The median run gains much less than the average curve suggests.
  • Changing the rater to Bradley-Terry helps about as much as smart pairing.

What it doesn't show

  • Real players: outcomes follow the exact model the raters assume, and skills never change.
  • Other pool sizes: every run has 32 players.
  • Pair rules with Elo or Bradley-Terry: they were tested with Glicko-2 only.
  • Other targets: 0.8 is one threshold; the gap differs at other values.

Reproduce

Run it yourself

git clone https://github.com/allenwang0/pairwise-ratings.git
cd pairwise-ratings
make setup     # install pinned dependencies (needs uv)
make test
make results   # 100 simulated runs per condition, about 1 minute
make report    # writes site/index.html
